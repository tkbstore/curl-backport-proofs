## 主張の強さは件ごとに違う

「成功」はどれも「手順書の P1・P0 の文が4つの関数で成り立った」を意味する。ただし P1・P0 の文の広さは件ごとに違い、
そのまま並べて「13件の修正が正しいと証明された」と読むと読み違える。性質を絞った件は次のとおり（詳細は各 md）。

- **CVE-2026-8927**: 環境変数から HTTP プロキシを読む1つの経路（場面 S）に絞った
- **CVE-2026-7168**: `CURLOPT_PROXY` で、前と新しいプロキシ文字列がどちらも NULL でない場面に絞った。switch の case を減らすため FTP などを無効にした構成で、Debian の実際のビルドとは違う
- **CVE-2026-3784**: `proxy_info_matches` についてはすべての入力で述べた。その戻り値で接続の再利用が決まることは前提で、証明していない
- **CVE-2025-14524**: `Curl_sasl_start` だけ。Debian のパッチは上流が変えていない `Curl_sasl_continue` も直しているが、そこは証明していない。P0 には、性質のコミットの後で前提（`sasl_ir=1` など）を足した
- **CVE-2026-8924**: `dlen`・`clen` を2以上にし、P0 では `clen` を256未満にした
- **CVE-2025-10148**: `payload_len` が負でない、`payload_remain` が正でない、を前提に置いた（その2つの枝の `failf` は可変長引数で、Certora/clean の引数の規則で評価できない）
- **CVE-2026-1965**: 証明したのは `_2` のパッチが直した規則（Negotiate を求める要求は、まだ Negotiate していない接続を照合の段で即座に受け入れない）。CVE の本体（資格情報の照合）は `_1` にあり、手順書で対象外にしている

外部関数の仕様はどの件も仮定である。弱い形に寄せた件が多いが、CVE-2026-3783 の `http_output_bearer` のように、実物より狭い仕様の件もある（各 md の「仮定した外部仕様」）。

## 手順書から外れたところ

- **D0 の取り方**: 手順書 §3 は D0 を「当てる前の 8.14.1」と書いた。担当 A の4件は「Debian の series で、このパッチの直前の状態」とした。
  CVE-2026-1965 と 8286 は、素の 8.14.1 には対象の関数の形が無い、またはパッチが当たらないため。4873 と 5545 は、関数の本体が素の 8.14.1 と同じだった。
  各 md に理由を書き、手順書は変えていない
- **性質のコミット後の変更**: CVE-2025-14524（P0 に前提を追加）、CVE-2026-8924（前提を狭めた）、CVE-2025-10148（`Curl_rand` の仕様を弱め、2つの前提を置いた）。どれも md に記録した
- **`static` 関数の保持**: CompCert が消さないよう、参照するだけの大域変数を `epilogue.h` に置いた（C1 の Case 2・3・5 と同じ扱い）
- **`lean/build.sh`**: エラーの行を拾う正規表現に `_` を足した（担当 D）。`Deb2026_3805Common.lean` のように名前に `_` を含むファイルのエラーが表示されなかったため。回数の数え方は変えていない
- **統合のマージコミット**: 担当 B と C のブランチを入れたマージコミット（598cc06・ba45166）は、`lakefile.toml` の roots にまだ入っていない担当のモジュールを含む。
  そのコミット単体ではビルドできない。最後のマージ（4e2cc39）でそろう。作り直す操作（`git reset --hard`）は許可されなかったので、そのままにしている

## 分かったこと

- **写す手間は、Debian の注記ではなく 8.14.1 と上流の関数の形の違いで決まった。** 13件のうち、D 側の書き換えが0行または名前だけだったのが7件
  （1965・4873・5545・8286・3805・14819・3784）。大きく書き換えたのは 8927・14524・10148 の3件で、どれも 8.14.1 の関数の形（戻り値の型、
  出力引数、別の関数に分かれているか）が上流と違った。Backported-by の注記がその違いを書いていたのは 7168 と 8286 だけで、10148 では場所は合っていたが量は分からなかった
- **対象外の1件は「バックポートが上流と別の仕組みで同じ効果を出している」件だった。** CVE-2026-5773 は、上流が `lib/protocol.c` の表の値を変え、
  Debian は `smb_connect` で `connkeep` を `connclose` に変えた。読む関数も違うので、§4 の「同じ形の定理」が立たない。
  手順書 §4 の対象外の例（停止しない・解放の有無・2つの実行の比較）には無い理由なので TK の判断に回し、2026-10-28 に対象外のままとなった
- **解放後の使用（CVE-2026-3805）も述べられた。** 原因の「同じブロックを2つの変数が指す」を、CURLE_OK のとき別々に所有されたブロックを指す、という事後条件で述べた。リークの側の修正は性質に含めていない
- **2件目以降は速い。** 同じ関数の族では、最初の件で作った戦術や補題がそのまま使えた（担当 A: 1965 が約2時間、続く3件は4〜6分）
